# Autonomy orchestration — 3.1

This is an agent-run production workflow, with durable local scheduling and real
provider calls made through tools. These instructions supersede old per-shot approval
and mandatory best-of-N rules in the retained compatibility references.

## Optimize for finished, coherent cinema

The agent handles research extraction, story alternatives and critique, shot graphs,
image references/prompts, generation, source overlays, Flow operation, downloads,
visual review, targeted repair, assembly and export. Use writer/editor/historian
perspectives within the current agent; this is not a requirement to spawn agents.

Start with a small representative visual family, including the opening/ending relation
and hardest transition. After G2, derive related frames from locked masters, not from
fresh text-only prompts. Make independent jobs executable while dependencies wait.
One failed hero transition must not stop unrelated ordinary shots.

Use staged candidate effort: routine image/video first output, inspect, then another
only if needed; hero/state-defining assets should have distinct useful alternatives.
The queue's candidate_n caps total requests per job revision. Changing a job contract
starts a new revision while the overall provider budget continues counting past work.
No empty placeholders or automatic generic motion should substitute for missing intent.

## Local graph vs provider execution

`production_runtime.py` persists job revisions, input hashes, claims, receipts,
candidates, semantic reviews, selections and event history. Frames referenced by a
dependent shot must be registered, intact and accepted by their producing job. Flow
Extend dependencies must have an accepted clip. Missing references/cycles block only
execution until repaired; corrupted manifests fail loudly.

`next` identifies ready jobs and specific reasons for others. `claim` reserves one
output and writes an agent dispatch packet before external execution. Once claimed,
never submit the same job again because a call timed out or a turn ended. Look up the
tool handle/Flow asset card and reconcile its actual state. A local ACTIVE record is
not proof that a remote process is still running. Never wait on a guessed handle.

## Boundaries and escalation

Routine AUTO work is selected by the agent after factual/visual and technical review.
REVIEW work is generated and prepared automatically; only its consequential selection
goes to the relevant human gate. BLOCK means do independent work while resolving the
specific factual/creative/access issue. Register source truth before generation.

Use existing user authorization for a finite initial production wave. The output caps
in `00_execution_policy.json` are scheduling limits, not currency estimates or new
permission rituals. Never invent a credit price. Refresh live prices before a material
paid expansion; present the batch total and unresolved decisions together if needed.

Do not change account-wide Flow confirmation settings merely for convenience. Within
already authorized production, operate confirmations yourself and use bounded Agent
requests. Ask only when a broader authorization or user-only login action is necessary.
